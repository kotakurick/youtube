# 010-online-shaming

テーマ: themes.csv の135「ネットで誰かを叩く人は何%か。なぜ人は私刑をしてしまうのか」（時事の枠。恋愛・結婚の外）

## いまどこまで・次に何をする・未決のこと（2026-10-10）

- いまどこまで：材料を集めて一次資料で確かめた（`research/japan.md`・`research/academic.md`、`sources.csv` の S1〜S25。★照合は未）。構成案 `outline.md` の第1版を `review-rival` に見せ（`review/rival-outline.md`。締めが対 考えすぎる葦で負け、ほかは勝ちか引き分け）、指摘を入れて第2版にした（新しさの中心を「ふつうの人が正しいつもりで」に移す、数え方の発見、締めの数字をそろえる、第2・3章に動く絵、叩かれた側の1分、予想の選択肢）。
- 次に何をする：オーナーに構成案を確かめてもらう（`outline.md` の「オーナーに確かめたいこと」5つ：INMU KING の扱い・架空の動画・締めの一文・ミクロ・タイトル）→ 答えを入れて台本 `script.md` へ。
- 未決のこと：上の5つ。締めは案A・案Bのどちらか。ミクロを残すか。
- オーナーの答え（2026-10-10）：
  - 「inmuking」は「INMU KING」（2026年8月公開。淫夢のネタを使ったAI楽曲）のこと。もとのネタは実在の出演者の特定・晒しを伴ったとされる（未確認）ので、動画の中では名前も画面も出さず、「晒しがネタ（ミーム）になり、元の人から離れて遊びとして続く」という型として扱う案（構成案で確かめる）。
  - 構成は **B案**（008 と同じ。「今日の答え合わせ」カードと最後の判定をやめ、問いは物語の中で1つ、予想タイムの答えは第2章か第3章の山場で1回だけ明かす。最後は短い結論 → ミクロ → 教訓）。
- 方針（壁打ちのセッションから）：2026-10-10 の方針（事実の可視化＋仮説の解説。シミュレーションは使わないか1場面まで）。実在の炎上・私刑の件は名前も画面も出さず型として扱う。被害者の件は特に慎重に。他人の投稿・動画を素材にしない。叩く人を見下さず誰でもやりうる形で描く。政治の件は避けるか中立に。人物は紫の猫（`kind="plain"`）。意味の色は構成案で決める。

## 質の最低ライン（公開前）

- [ ] テーマが伸びている分野・問いに入っている（themes.csv の優先度、ベンチマーク分析）
- [ ] タイトル・サムネイルは自分たちの型で作り、他チャンネルの言い回しをまねていない
- [ ] サムネイルがチャンネルの様式どおり。大きな文字は2〜3かたまり、主題は1つ、数字は入れても1つ
- [ ] 最初の60秒で問いが出る。動画の最初の1割のうちに最初の具体的な数字が出る
- [ ] クイズは冒頭の予想タイムだけ。章ごとに1つ、自分に当てはめられる場面（実験・自分に当てはまる数字・日ごとの再現）が問いの形でなくある
- [ ] 事実を分かりやすく見せる独自のグラフが1つ以上ある（シミュレーションは使っても1場面・条件2つまで）
- [ ] 事実と仮説を声で言い分けている（スタンスはとってよい）
- [ ] 出典を要所で画面に出している
- [ ] 画面が10〜20秒ごとに変わる。グラフや文字だけの画面が30秒以上続かない
- [ ] `npm run check` の直すものが0件（図と図、図と文字、字幕の帯に何も重なっていない）
- [ ] 人物の絵柄がチャンネルの決まりどおり（回ごとに変えない）
- [ ] 読み上げが1分390〜400字前後で、長い間がない
- [ ] 読み上げる数字が1分に4〜5個まで。丸めて言い（約3割、4人に1人）、細かい値は画面に出している
- [ ] 冒頭が物語（1人の人物・情景・歴史の一場面）から入っている。数字を並べて始めていない
- [ ] 締めは答えのあとに「教訓」で終えている。答えだけ・問いかけ・登録の呼びかけで締めていない
- [ ] 企画カードが埋まっている（痛み・逆説の一文・この動画だけの数字・日本の数字・絵で分かる瞬間・ミクロ）。`review-rival` で「負け」が残っていない
- [ ] 面白さの仕掛け（先回り・比喩と回収・ミクロ・締めの一文）が台本にある（`lint_script.py` のエラーが0）
- [ ] 結論を数字の範囲内ではっきり言っている（助言はしていない）
