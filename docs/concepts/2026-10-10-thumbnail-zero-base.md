# サムネイルをゼロから考え直す（2026-10-10 案）

オーナー「明朝体も2色もこだわりはない。最適な企画者がゼロベースで、あるべきサムネイルを検討してほしい」への答え。
**決定ではなく案**。決まったら `docs/decisions.md` と `docs/brand.md` のサムネイルの行を書き換える。

## 1. サムネイルの仕事

うちの動画が見られる場所は、ほとんどが**おすすめの欄**（ホームと、競合の動画の横・下）になる見込み。登録者がいないうちは検索もほぼない。
そこでのサムネイルの仕事は3つだけ。

1. **0.5秒で主題が分かる**：スマホの幅で横168〜360px。読めるのは大きな文字のかたまり2つと、絵の主役1つまで。
2. **自分の話だと思わせる**：見る人が「自分か、身近な誰か」を思い浮かべる名詞（普通の相手・年収・40代の結婚）。葦の116本で、上位と下位を分けたのは作りではなくこの名詞だった（`research/benchmark/teardown/kangaesugiruashi-thumbnails.md`）。
3. **タイトルの続きを知りたくさせる**：タイトルと同じことを言わない。サムネイルは「感情」、タイトルは「中身」。

逆に、サムネイルの**作り込みの差では、伸びた群と伸びていない群が分かれなかった**（16チャンネル。`research/benchmark/thumbnails.md`）。伸びた群に共通したのは「様式を1つに固定」「文字2〜3かたまり」「主題1つ」。つまり、**凝ることより、毎回同じ型で安く速く作れること**のほうが効く。

## 2. いまの案の問題（オーナーの「相性が悪い」の中身）

- 絵の主役（人）をコードで描いていた。コードの線では、表情・ポーズ・質感が出ない。
- 地の2色・明朝体など、効くかどうか分からない決まりに手間をかけていた。明朝体は細い線があり、小さな画面では太いゴシックより読みにくい。
- 回ごとに構図をゼロから作っていた。様式の固定と逆。
- 採点が Claude のレビューだけだった。

## 3. 競合の中での立ち位置

おすすめで隣に並ぶのは、ほぼ次の3つ（`research/benchmark/thumbnails.md`）。

| 競合 | 見た目 |
|---|---|
| lovebynumbers・love_observation | 黒地に、男＝青・女＝赤の人形やシルエット。白い2行の文字 |
| 考えすぎる葦 | 暗い映画風の画像に、画面の半分を占める特大の文字（質感つき） |
| データで語る棒人間 | 棒人間＋グラフ、問いの形の文字 |

「黒地＋赤青の人」はもう2チャンネルが持っていて、まねると埋もれる。写真のようなAIの人物は、伸びていないチャンネル（nippon_data・datademirunippon など）に多く、ありふれている。
**うちだけが持っているのは「猫」と「数える」**（チャンネル名「吾輩は数える猫である」、本編の主人公の猫、群衆を数え直す絵）。

## 4. 推す様式：「感情のある猫 ＋ 特大の言葉 ＋ 数える印1つ」

| 要素 | 決まり |
|---|---|
| 主役 | **本編の主人公の猫**（`render/src/lib/Cat.tsx` の猫を手本に、画像生成AIで質感のある絵にする）。顔が大きく見える寄り。表情ははっきり（困る・驚く・固まる）。男女の回は青の猫とオレンジの猫を同じ大きさで |
| 文字 | 画面の3分の1以上。**太いゴシック**、白か黄に黒い縁。2かたまりまで。1かたまりはその回の名詞（普通の相手）、もう1つは感情の言葉（のに、いない） |
| 数える印 | 1つだけ：小さな群衆の中で1人だけ光る、指で数える、数字1つ、のどれか。毎回同じ位置 |
| 地 | 回ごとに1色（その回の情景の色）。チャンネルの印として、毎回同じ位置に同じ色の小さな帯かふち |
| 置き方 | 毎回同じ：猫は右、文字は左（右下は再生時間の表示で隠れるので、大事なものを置かない） |

推す理由：

- **猫は表情を出せる**のに、実在の人に見えない（AIの開示も要らない）。顔のない人形より感情が伝わる。
- 本編を見た人に、サムネイルとチャンネルが結びつく（主人公の猫がそのまま出る）。
- 赤青の人形・暗い映画風の画像・棒人間のどれとも違う。
- 猫の絵は、ポーズと表情の組み合わせを一度まとめて作れば、回ごとに選ぶだけで済む。

心配な点：

- 「動物のかわいい動画」に見えて、データの話だと伝わらないおそれがある。→ 文字に名詞を入れ、数える印でデータの話だと示す。
- 画像生成AIで、本編の猫と同じ猫を毎回そろえて出せるかは、まだ試していない。→ まず10枚作って確かめる。

## 5. 比べる相手（同じ型で2つ。テストにかける）

様式は意見では決めきれない。**YouTube の「テストと比較」**（1本にサムネイルを3枚まで載せ、総再生時間の多い1枚が残る。https://support.google.com/youtube/answer/13861714 ）で決める。

| 案 | 主役 | ねらい |
|---|---|---|
| **A 猫**（推し） | 感情のある主人公の猫 | うちだけの絵。表情で引く |
| B 人形 | 顔のない白い人形（今回 Canva で作ったもの） | 人の姿で「自分の話」に見せる。表情は弱い |
| C 数える | 100人の群衆で、条件を通る数人だけ光る＋数字1つ | データの話だと一目で分かる。棒人間に近い |

文字・置き方・地の決まりは3案とも同じにして、主役だけを変える。1〜6本目まで毎回3枚を載せ、勝った回数で様式を仮に決める（6本ではまだ仮説。10本で見直す）。

## 6. 作る仕組み（Claude が苦手な所を外す）

| 工程 | 担当 | 中身 |
|---|---|---|
| 絵の素材集 | 画像生成AI（Canva のコネクタ。クラウドで Claude が回せる） | 猫：ポーズ×表情を20枚ほど。地と同じ単色の背景で作り、切り抜かずに使う |
| 型 | コード（`render/src/lib/` の部品。一度作って固定） | 文字・素材・印・地の色を差し込むだけの枠。座標は型が持つ |
| 回ごとの中身 | Claude | 言葉2かたまり（案を5つ→3つ）、素材の番号、印、地の色 |
| 機械のチェック | コード | 168px に縮めて文字が読めるか、文字と地の明るさの差、かたまりの数、右下に何もないか |
| 見比べ | コード＋レビュー役 | 競合のサムネイルの間に並べた一覧（ローカルの取得物で）。レビュー役は明らかな失敗を落とすだけ |
| 決める | YouTube の「テストと比較」 | 3枚を載せて、残った1枚。結果は回の README と、この表に書きためる |

## 7. 決めてほしいこと

1. この方向（様式を1つに固定、主役は猫を推し、人形・数えるとテストで比べる）でよいか。
2. 文字は太いゴシックに替えてよいか（明朝体の決まりを外す）。
3. 猫の素材集を Canva の画像生成で作ってよいか（サムネイルだけ。本編は今までどおりコードの猫）。
