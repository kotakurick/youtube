# 制作パイプラインの品質を上げるアクション（検討メモ）

2026-10-04。オーナーの依頼「品質を高めるのに必要なアクションを、調査もして検討する」への回答。
ここに書いたのは**提案**で、決定ではない。採用したものは `docs/decisions.md` に日付付きで追記する。

## 0. 前提：今の状態

- まだ1本も通して作っていない（`episodes/` は `_template` だけ）。どの工程も実際の回では試していない。
- 一番整っているのは台本（`script-style.md`、`lint_script.py`、script-review スキル）と画面の重なりチェック（`npm run check`）、音量（`npm run master` で -14 LUFS／-1 dBTP）。
- 手作業か未整備のもの：字幕の時刻（手書き）、出典の照合（全部目視）、読み間違いの発見、概要欄・チャプター、公開前の確認、公開後の振り返り。

**一番効くのは、仕組みを増やすことより「1本目を早く最後まで通して、どこで詰まるかを見る」こと。** 下の提案は、その1本目の中で必要になる順に並べた。

## 1. 優先度A：1本目を作る中で入れる

| # | アクション | なぜ | 手間 |
|---|---|---|---|
| A1 | **仮通し（アニマティック）**：仮の音声と仮の絵（文字だけの場面でよい）で18分を最後まで流し、テンポ・章の長さ・「考える場面」の位置を確かめてから本番の絵を描く | 構成の問題を一番安い段階で見つける。Kurzgesagt は台本を約12稿書き直す。Remotion なら仮の場面は安く作れる | 小 |
| A2 | **音声の時刻から字幕と場面の切り替えを自動で出す**（音声合成の文ごとの長さ → 字幕の `[開始, 終了, 文]` と SRT ファイル） | 今は字幕の時刻を手で書く方式で、ずれの元になる。SRT を YouTube にも上げれば英語の自動吹き替え・検索にも使える | 中 |
| A3 | **出典の突き合わせを機械でやる**：台本の `[S1]` が sources.csv にあるか、画面に出す数字と sources.csv の値が一致するかをスクリプトで確かめる | ★の人による照合は残す。機械は「照合漏れ」と「写し間違い」を拾う役 | 小〜中 |
| A4 | **読み間違いを見つける**：出来た音声を文字起こしして台本と比べ、違う箇所だけ聞き直す。`yomi.tsv` にアクセントの列を足し、エンジンの辞書へ自動登録 | 18分を毎回耳だけで確認するのは漏れる。数字・単位・統計用語（中央値・有配偶率など）が特に危ない | 中（文字起こしの道具を入れるなら事前に許可が要る） |
| A5 | **グラフの誤解防止を部品の初期値にする**：縦軸は0から、割合は100%まで描く、2軸グラフは使わない、調査の年・人数・方法を画面に出す。`qa.ts` に足せるものは足す | 英国統計規制局（OSR）・英国統計局（ONS）の指針。「数字を誇張しない」という収益化ポリシーの約束を、部品の側で守らせる | 小 |

## 2. 優先度B：公開の前に

| # | アクション | なぜ |
|---|---|---|
| B1 | **公開前チェック表を1枚にする**：音量、読み間違い、字幕と台本の一致、画面の数字と sources.csv の一致、`npm run check`、AI開示の判断、他人の素材が入っていないか、公開設定（子ども向けでない・再生リスト・終了画面） | 今は `_template/README.md` に分かれて書いてある。1枚にすると漏れない |
| B2 | **概要欄を sources.csv と章から自動で作る**：出典一覧、チャプター（00:00 から、3つ以上、10秒以上）、シミュレーションの条件 | YouTube のチャプター条件に合う。出典の公開は Kurzgesagt・Johnny Harris でも信頼の要になっている |
| B3 | **「前の回との違い」を1行書いてから公開する**（問い・データ・結論・構図のどれが変わったか） | 2025-07 の改定で「大量生産・繰り返しのコンテンツ」は収益化の対象外と明記された。2026年は YouTube が「AI slop への対処」を最優先にしている。AI音声そのものは禁止されていない。危ないのは「同じ型の量産」に見えること |
| B4 | **タイトル×サムネイルを3案作り、「テストと比較」にかける** | 最大3案まで試せる。勝ち負けはクリック率ではなく総再生時間で決まるので、中身と合った案が残る。`brand.md` の「テストで決めるもの」をここで決められる |

## 3. 優先度C：公開のあと

| # | アクション | なぜ |
|---|---|---|
| C1 | **公開1週間後の振り返りシート**：最初の30秒の残存率、離脱の谷・見返しの山の時刻を、台本の段落に対応させて回のフォルダに記録する | YouTube Studio の「維持率の重要な瞬間」でこれが見られる（60秒以上・100回再生以上の動画）。今は記録する欄がない |
| C2 | **10本たまったら台本の決まりに反映する** | CLAUDE.md の「10本未満は仮説」をそのまま使う。同じ谷が10本で出たら `script-style.md` に足す |
| C3 | **訂正の手順を先に決めておく**：軽い誤り → 固定コメントと概要欄、重大な誤り → 非公開にして説明 | Kurzgesagt は偏りがあった動画を自分で消して説明した。誤りが出てから決めると遅い |

## 4. オーナーの判断が要るもの（勝手に決めない）

1. **AI開示ラベルの扱い**：YouTube のヘルプでは、アニメーションと合成音声のナレーションは開示不要。CLAUDE.md の「迷ったら付ける」とどう合わせるか（例：コードで描いた場面と合成音声だけなら付けない、と決めるか）。
2. **文字起こしの道具を入れるか**（A4。Whisper など。インストールは事前の許可が要る）。
3. **アニマティックを毎回の工程にするか**、1本目だけ試すか。
4. 残っている未決定のうち、品質に直接かかわるもの：**声**（5社の聞き比べの途中）、**1本目のテーマ**（9か2）。A2・A4 は声が決まらないと最後まで作れない。

## 5. 調べてもわからなかったこと

- YouTube の音量の基準（-14 LUFS）は公式ヘルプに数値がない。計測と二次情報による。今の `npm run master` の設定はそのままでよい。
- 有名チャンネルが外部の人に見せる試写や、アニマティックをやっているかは、公開された一次情報が見つからなかった。
- 字幕ファイルを上げると伸びる、という一次情報は見つからなかった（A2 は手間がほぼかからないので入れる価値はある）。
