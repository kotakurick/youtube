# ブランドの決まり（吾輩は数える猫である）

2026-10-04 決定（`docs/decisions.md`）。経緯と根拠は `docs/concepts/2026-10-04-brand-consult.md`。
数字（色・大きさ・動き）はコードの `render/src/lib/theme.ts` が正本。ここと食い違ったらコードに合わせて直す。

## 核

- **チャンネル名**：「吾輩は数える猫である」（略称「数える猫」）。夏目漱石『吾輩は猫である』のもじり。名乗りの一文（「名前はゴサ」など）は入れない（オーナー）。語りは人間のナレーターで、猫の一人称では語らない。
- **約束**：「よく聞くあの話」を、100人の絵と一次資料で確かめ、言える範囲ではっきり答える。毎回渡すのは、答え（〇△×）・自分がどこにいるか・教訓の3つ。
- **キャッチコピー**：「世の中の"たぶん"に、誤差つきの答えを。」
- **性格**：言い切る（煽らない）／公平（両側のデータを出す）／人に温かい（1人の物語から入る）／茶目っ気（ゴサの小さな反応）／正直（分からない所は「条件次第」と見せる）。
- **語り口**：です・ます、短い文、丸めた数字、1つの数字に時間をかける。「衝撃！」「【悲報】」「〜すべき」「女はこう」は使わない。

## 毎回同じにするもの／毎回変えるもの

| 同じ（型） | 変える（中身） |
|---|---|
| 色、書体（Noto Sans JP）、文字の大きさの段階 | 問い、物語の主人公と情景 |
| 字幕の帯、出典の書式と位置 | データの組み合わせ、グラフの種類 |
| 100人の群衆、人型1つ、追う1人の印 | シミュレーションの条件と見せ方 |
| 今日の答え合わせ・判定のカード、判定の音 | 判定の結果（〇△×の配分） |
| ゴサの決まり、章の扉 | 教訓、タイトルの言い回し、サムネイルの主題 |

公開前の確かめ方：枠（カード類）は合わせて1分以内／10本のサムネイルを並べて主題がすべて違って見えるか／2本の冒頭30秒を入れ替えて気づかれないなら作り直す。

## 標準構成（3章・13〜18分。長さはデータの量で決める）

| 時間 | 中身 |
|---|---|
| 0:00–0:40（最大1:00） | 物語の冒頭：主人公に寄る → 引くと100人の中の1人（群衆から入る回）。最初の数字は物語の中で1分以内（動画の最初の1割のうち）。0〜5秒に右上へチャンネル名が1.5秒（`ChannelTag`）。ロゴ・あいさつはなし |
| 0:40–0:48 | 今日の答え合わせ（通説を1行） |
| 0:48–1:45 | 問いの立て直し、予想タイム（4択。答えは判定で明かす。**答えが判定まで自然に出てこない問いを選ぶ**。章の中で順位を言いたくなる問いは避け、第2章・第3章の発見に向けた問いにする）、3章の道案内 |
| 1:45–6:15 | 第1章：身近な公的統計。自分に当てはめる場面 |
| 6:15–10:45 | 第2章：仕組み。もう一方の側のデータもここで出す。クイズ。終わりに「ここまでの答え合わせ」を1行 |
| 10:45–15:15 | 第3章：**別の角度で確かめる**。もしものシミュレーション・数え直し（割合を数に直すなど）・反対の証拠のどれか。シミュレーションはデータがそろう回だけ（方眼の背景。ここだけ1000人も可） |
| 15:15–16:30 | 答え合わせ：通説 → 証拠3つ → 〇△× → 予想の答え |
| 16:30–17:40 | 教訓：冒頭の人物に戻り、「だから世の中はこう見える」と一般化する（助言にしない） |
| 17:40–18:00 | 終了画面20秒（次の1本と再生リスト。ナレーションなし） |

- 時間は18分の回の目安。データが少ない回は13分ほどでよい。引き延ばさない（1本目は約13分。2026-10-04）。
- **言い切るのは、誤差の幅の中で言えることまで**。推計や標本の小さい数字は「推計で〇割ほど」「少なくとも〜とは言えない」まで。
- **正しさは門、面白さが最優先**（2026-10-05）。うそ・誇張・助言・偏見は門として必ず止める。門を通った指摘どうしが割れたら、**心の動き・深さ**を優先する。断り書きは画面の隅と概要欄へ回し、声では言い切る。

- 登録のお願いは30〜40%の位置に画面の文字で1行だけ。声で登録を呼びかけて締めない。
- **毎回の締めのひと言**：教訓の締めの一文のあと、「数えてみると、景色が変わりました。」（2026-10-05 オーナー決定）。字幕は出さない（台本で〔字幕なし〕）。画面は毎回同じアニメーション `SignOff`（`render/src/lib/SignOff.tsx`）：丘に猫2匹、100個の点が数えられて並び、夜が広がって点が星になり、夜空にこの一文とチャンネル名（2026-10-05 オーナー「字幕は要らない。猫がいる、クオリティの高い共通アニメーションで」）。
- 章の切り替えは墨のワイプ＋章の扉（`ChapterCard`、3秒以内）。そのあと右上に章の位置の点（`ChapterDots`）。

## ゴサ

- 置き場所は右下（足元 y=880、中心 x=1690）。大きさは体の直径で S96／M140／L220。画面に出るのは全体の約9%。
- 暗い背景では反転版（白い体に墨の目）を使う（`Gosa dark`、静止画は `_dark.svg`）。
- 表情の間はなめらかにつながる（`render/src/lib/Gosa.tsx`。絵の正本は `assets/characters/gosa/make_gosa.py`）。
- **ひげ＝確かさ**：〇と×は短い（`assertive`）、△は長い（`depends`）。
- 吹き出しは「答え合わせ。」「ひげ、短め。」「ひげ、のびます。」「！」だけ。声・鳴き声はなし（しゃべるかは未決定）。
- 音は表情ごとに1つ（驚き・言い切り・条件次第・ジト目・ひらめき・焦り）。30秒に1回まで。
- 文字や数字に重ねない。数字と出典の画面ではおとなしくする。判定するのは「説」で、人ではない。
- **男女の対立の回**：審判に徹する。片方の性別に向けたジト目・落胆は使わない。サムネイルには出さないか「考え中」だけ。

## 見た目

- **区画**（1920×1080）：問い y56–176／主役の絵 y200–820（出典があるとき。ないときは y880 まで）／出典 y844–876（グラフの左下）／字幕 y920–1000／下80pxは何も置かない。字幕の帯の上は28px空ける（`npm run check`・`npm run storyboard` が「字幕の帯に近すぎます」で止める。2026-10-05 オーナー「字幕と近い」）。
- **文字**：主役の数字200、章の扉96、問い72、グラフの値64、本文44、ラベル40、字幕54、出典28。28px未満は作らない。スマホ確認は640×360に縮めて読めるか。
- **色**：色はデータの意味（男・女・注目・その他）にだけ使う。話の対象外の人は薄い色（opacity では薄くしない）。〇△×は墨だけ。強調は蛍光ペンの黄（文字や数字の下に敷くだけ）。
  - **お金の回の意味の色**（2026-10-05 オーナー「色合いが淡白すぎる」）：男女の話でない回は墨と灰だけになり淡白だったので、お金の意味ごとに色を決める。金（`C.gold`）＝資産・利息（r）、青緑（`C.teal`）＝給料・降る雪（g）、赤（`C.debt`）＝借金・損。それぞれ淡い色（`goldTint`・`tealTint`・`debtTint`）を面に使う。性別の色とは混ぜない。雪玉（`Snowball`）・村の目印（`Village`）・借金（`Money`）はこの色で描く。
- **人型**：男女の面積をそろえる（誇張しない）。その他・無回答は丸い胴。100人の場面で1人の高さ64px以上。
- **物語の主人公（猫）**（2026-10-05 オーナー決定、素案F・トラ柄）：冒頭・寸劇・教訓など、寄って描く物語の場面の登場人物は猫にする（群衆・データの人数は人型のまま）。部品は `render/src/lib/Cat.tsx`（見本は静止画 `cat-poses`、選んだときの素案は `cat-sheet`）。
  - 形：丸い頭・大きめのとがった耳（内側は淡い色）・洋なし形の胴・丸い足先・巻いた尾。線は描かず、べた塗り。
  - 模様：額に3本・胴の両脇に1本ずつのしま（体の色の濃い色）、墨の細いひげ2本ずつ（ゴサのひげと違い、端に横棒を付けない）。
  - 色：男性＝青、女性＝オレンジ、引き合わせ役などその他＝灰。墨（ゴサの色）は使わない。
  - 目と口はゴサと同じ形（白目に小さい黒目、細いωの口、鼻なし。オーナー「目と口はゴサと同じトーン」）。
  - ポーズ5つ（stand・sit・phone・walk・down）、表情5つ（normal・happy・surprised・think・sad）。3〜5秒ごとにまばたき。
  - 同じ場面に猫と人型を混ぜない（向かい合う相手・引き合わせ役も猫にする）。
- **グラフ**：看板は100マス（群衆がそのまま並び直す）。棒は上の角だけ丸く、値は直接書く。注目の値には誤差棒（95%の範囲）。
- **シミュレーション**の場面は方眼の背景（`SimBackground`）と「シミュレーション（条件は概要欄）」の札（`SourceNote sim`）。実データは無地。
- **動き**：ばねは3種類（文字・カード／群衆／ゴサと答えの数字）。回転・文字の弾み・クロスフェードは使わない。続く場面は1つ以上の要素を引き継ぐ。

## 画面のチェック

- 書き出す前に `npm run check -- <回のid>` で、重なり・28px未満の文字・はみ出しの「直すもの」を0にする（`render/README.md`「画面のチェック」）。

## 演出の強さ

- 普段の画面は淡泊に、ただし止めない。動きには意味を持たせる（人が集まる・並び直す・1人に寄る）。飾りの動きは使わない。
- 凝るのは3か所だけ：答えの数字が出る瞬間（`HeroNumber`）、判定（`Verdict`）、シミュレーションの結果（群衆の並び直し・`Slider`）。
- 見せ場以外は使い回せる部品で作り、1本の手間を増やさない（2026-10-04、PCのセッションでの相談）。

## 音

- BGM：YouTube オーディオライブラリから5〜6曲（物語・考え中・シミュレーション・判定・教訓）を固定し、20本は替えない。2026-10-04 の割り当て：冒頭の物語と教訓前の戻り＝Sizzr - Schwartzy／第1・2章＝Stayin' Lazy - Godmode／第3章＝Jomon Grove - The Mini Vandals／判定＝Traversing - Godmode／教訓と終了画面＝Away - Patrick Patrikios（`docs/decisions.md`）。歌なし、テンポ90〜110。声より約19dB下げる（`Episode` が自動で下げる。曲ごとの音量の違いは `npm run bgm` が測ってそろえる）。
- 効果音はコードで作る（`render/scripts/make-sfx.mjs`）。判定は「1.5秒の刻み → 0.3秒の無音（BGMも止める）→ 打撃 → 印ごとの余韻」。
- 仕上げは -14 LUFS、ピーク -1 dBTP（`npm run master`）。
- 字幕は常に焼き込み、帯の幅は固定。1枚は1行（横長24字・縦長16字）まで。2行にすると帯が上に伸びて絵にかかるため（2026-10-04、画面のチェックで判明）。長い文は `tts/narrate.py` が自動で区切る。

## パッケージ

- **タイトル**：型A 答えをにおわせる断定／型B シミュレーションの結果／型C 自分に当てはめる。数字は1つまで。【〇〇学×〇〇学】、「」、「なぜ〜なのか」は使わない。「？」は付けない形で始め、テストで確かめる。
- **サムネイル**（`Thumbnail`。`<回>-thumb` と `<回>-thumb-ink`）：紙色の地＋墨の文字帯（2かたまり）＋左に100人の10×10（主役だけ色）＋右下にゴサ。〇△×は出さない。全面墨の地とテストで比べる。ゴサのあり・なしも1〜8本目でテストし、8本目のあとに仮に決める。
- **再生リスト**：「100人で数える婚活」「恋愛・結婚の答え合わせ」「あなたは何%側？」＋全話の「恋愛・結婚を数える」。
- **ショート**：3本目から、長尺1本につき1本（縦に組み直した30〜50秒、公開の1〜2日後）。`episodes/<回>/scenes/Short.tsx` に書く（見本は `demo-short`）。
- **最初の10本で見る数字**（目安。仮説）：クリック率4%、30秒時点の維持率65%、平均視聴率35%、1,000回あたり登録3人。
