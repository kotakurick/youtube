# 台本の書き方（語りの決まり）

2026-10-04 作成。台本（`episodes/<回>/script.md`）を書くときと、推敲するときの決まり。
決定済みのルール（`CLAUDE.md`「作り方の基準」、`docs/brand.md`「語り口」、`docs/decisions.md`）を1か所に集め、耳で聞く原稿に必要な書き方を足した。
機械で確かめられるものは `scripts/lint_script.py` が確かめる。推敲の手順は `.claude/skills/script-review/SKILL.md`。

AIっぽい言い回しの直し方は、yomiyasu（https://github.com/nanaism/yomiyasu 、MIT License）の考え方を参考にし、ナレーション向けに作り直した。

## 1. 語り口（決定済み）

- **です・ます**でそろえる。だ・である調を混ぜない（`docs/brand.md`）。
- **短い文**（決定済み）。1文は40字までを目安にし（40字は目安で、データの裏付けはない）、読点は2つまで。長い文を分けるのは、つながり（理由・順序・対比）を次の文のつなぎ言葉で残せるときだけ。
- **言い切る**。数字の範囲の中で、結論ははっきり言う。言い切れない部分は「条件によって変わる」と言い、シミュレーションで見せる。
- **煽らない・見下さない**。「衝撃！」「【悲報】」「ヤバすぎ」「女はこう」「男はみんな」は使わない。
- **助言しない**。「〜すべきです」「〜しましょう」「〜を選んでください」「おすすめです」は、健康・お金に限らず台本では使わない（呼びかけは予想タイムの「考えてみてください」だけ。章の中では使わない。13章）。
- **驚きは事実の言い方で出す**。「思ったより、ずっと少ない数字です」のように、感情の言葉は事実にくっつけて使う。伸びたチャンネルは驚きの言葉を少し使っている（`research/benchmark/style.md`）が、煽りのラベルにはしない。

## 2. 構成（決定済み）

- **冒頭は物語**：1人の人物・情景・歴史の一場面から入る。数字を並べて始めない。最初の具体的な数字は、物語の中で1分以内（動画の最初の1割のうち）に出す。冒頭は40秒が目安で、最大1分。
- **人物を番号で呼ばない**（「27番さん」は失礼に聞こえる。2026-10-04 オーナー）。声では役割（孫娘・母・会社員）か「彼・彼女」で呼び、年齢は画面の名札に出す。
- 標準構成どおりに並べる（`docs/brand.md`「標準構成」）。**クイズは冒頭の予想タイムの1回だけ**（2026-10-07 オーナー。13章）。章ごとに1つ、視聴者が自分に当てはめられる場面（自分に当てはまる数字・日ごとの再現・実験）を、問いの形にせずに置く。
- 第2章で、もう一方の側（男女なら両方）のデータを必ず出す。
- **シミュレーションの回は、予想の前に条件を見せる**（2026-10-06 オーナー）。声は1〜2文（「数字は、なるべく実際の調査に合わせました」など）で、画面に条件と根拠の表を出す（`docs/brand.md`「シミュレーション」）。
- **締めは教訓**：答えを出したあと、冒頭の人物に戻り、「だから世の中はこう見える」と一般化する。答えだけ・問いかけ・登録の呼びかけで締めない。教訓も助言にしない。
- **毎回の締めのひと言**：教訓の締めの一文のあとに〔間・長〕を置き、「数えてみると、景色が変わりました。」を必ず入れる（2026-10-05 オーナー決定。文言は毎回同じ）。書き方は `〔字幕なし〕数えてみると、景色が変わりました。〔間・長〕`（字幕は出さず、画面は SignOff のアニメーション）。

## 3. 数字（決定済み）

- 読み上げる数字は **1分に4〜5個まで**（台本なら約400字に4〜5個）。数字を並べず、1つの数字に時間をかける。
- 読み上げる数字は**丸める**：「28.25%」ではなく「約3割」「4人に1人」。細かい値は画面に出す。
- 「調査によると」「研究では」を言いすぎない。出典は画面に出し、口では中身を語る。
- 数字を出す文には、`sources.csv` の id を `[S1]` のように付ける（読み上げ用のテキストを作るときに消える）。
- 画面の色を言うとき（「金色の線が r」「利息は金色」など）は、その回の**意味の色**の名前で言う（`docs/brand.md` の「回ごとの意味の色」）。「濃い線・薄い線」「黒・白」のように見た目の濃さで呼ばない。色を変えたら、台本の色の言い方も同じ日に直す（2026-10-05。2本目で2回ずれた）。

## 4. 耳で聞く原稿の書き方（2026-10-04 追加の目安。データの裏付けはないので、読み上げて不自然なら直してよい）

- 記号を読み上げに頼らない：`%` は「パーセント」と読まれるが、`〜` `／` `・` `（）` `【】` `「」の中の長文` は読み方が揺れる。範囲は「18歳から34歳」、比は「4人に1人」と言葉で書く。
- 同じ音の言葉を近くに置かない（「市場（しじょう／いちば）」「人気（にんき／ひとけ）」など読みが割れる語は `tts/yomi.tsv` に足す）。
- 漢字の熟語を3つ以上続けない（「婚姻件数減少傾向」→「結婚する人の数は、減り続けています」）。
- 英字の略語は最初に言い換える（「SNS」は使ってよい。「MBTI」などは初出で説明する）。
- 指示語（これ・それ・この数字）は、何を指すかが直前の1文で分かるときだけ使う。耳では前の画面に戻れない。
- 同じ文末（「〜です。」「〜です。」「〜です。」）が4回以上続いたら、体言止めか問いかけを1つ混ぜる。

## 5. AIっぽい言い回しを消す（yomiyasu を参考に作り直し）

直すときの最優先は、**意味を変えないこと**と**足さないこと**。

- 主張・比重・言い切りの強さ・文の働きを変えない。推量（〜でしょう）を勝手に断定にしない。断定を勝手に弱めない。
- 元にない数字・原因・例・人物を足さない。足りないときは書き手（Claude の場合はオーナー）に確かめる。
- 言い回しが持っていた含み（「ようやく」の待った感じ、「〜てしまった」の後悔など）は、別のふだんの言葉で残す。
- 定着した慣用句（「骨が折れる」「目から鱗」など）は残す。物語の情景の比喩も残す（冒頭の物語は情景で引き込む場所なので、比喩を消して説明文にしない）。

消す・言い換える言い回し（一覧は `scripts/lint_script.py` の `SLOP`）：

| 種類 | 例 | 直し方 |
|---|---|---|
| 前置き・後置きのラベル | 「重要なのは」「結論から言うと」「注目すべきは」「〜というわけです」「〜に他なりません」「〜と言えるでしょう」 | 要点から言う。評価を担っているなら述語に移す（「〜が大事です」） |
| 決まり文句の締め | 「いかがでしたか」「参考になれば幸いです」「ぜひ〜してみてください」 | 消す。締めは教訓 |
| 大げさな熟語 | 「真実」「真理」「宿命」「究極」「深淵」「残酷な現実」 | ふだんの言葉にする（「本当のところ」「よくあること」） |
| 中身のない言葉 | 「本質」「解像度」「腹落ち」「肌感」「熱量」「温度感」 | 何をどこまで調べたのかを、元の情報の範囲で言う |
| AIが好む比喩の動詞 | 「効いてくる」「溶かす」「潰す」「踏み込む」「浮き彫りになる」「紐解く」 | ふだんの動詞にする（「わかる」「調べる」） |
| 英語の直訳 | 「〜した瞬間」「〜を示唆している」「XではなくYです（修辞だけのとき）」 | 「〜するとすぐ」「〜と考えられます」。否定が意味を担うときは残す |
| 擬人化 | 「データが語っています」「数字が教えてくれます」 | 「データを見ると、〜です」 |

## 6. 推敲の流れ

1. 構成案（`outline.md`）を標準構成の枠で書く。
2. 台本（`script.md`）を書く。
3. `python scripts/lint_script.py episodes/<回>/script.md` で機械チェック。
4. 推敲（`.claude/skills/script-review/SKILL.md` の手順）。直したところと、残したところを短く書く。
5. もう一度チェックを通す。
6. ★ オーナーが一次資料と照合し、読み上げて違和感を確かめる。

## 7. 声への指示（2026-10-04 追加）

台本の中に〔 〕で書く。読み上げず、字幕にも出ない。`scripts/lint_script.py` も数えない。

- **間**：〔間・短〕〔間〕〔間・長〕の3つだけ。文のあとに 1.0／1.5／2.2 秒の無音が入る（指示がないときは 0.5 秒）。2026-10-05、オーナー「文と文の間はもっと長く」で 0.25 秒から延ばした（〔間〕の3つもそれに合わせて延ばした）。
- **字幕の切れ目**：字幕は1行24字までで、`tts/narrate.py` が自動で切る（読点 → 助詞のあと の順。助詞の前がひらがなのときは語の途中とみなして切らない）。切れ方がおかしいときは、台本の文の中に `｜`（全角の縦線）を書くと、そこで切る。`｜` は読み上げず、`scripts/lint_script.py` も数えない。
  - 使う場所は絞る：答えを言う直前、問いかけのあと（視聴者が考える時間）、意外な数字の直後。長い間を続けない（1章に数か所まで）。
- **語り方**：英語で書き、効かせたい文の前に置く。次の指示まで続き、場面（## 見出し）が変わると戻る。
  - 何も書かないと「warm, clear, even-toned narration」（抑揚を抑えた語り）。速さ（brisk pace）は自動で付くので書かない。
  - **多用しない**。感情の起伏が激しくなりすぎる（2026-10-04 オーナー確認）。1章に1〜2か所まで、問いかけ・答えの直前など効かせたい所だけ。
  - 弱い言い方で書く：〔slightly thoughtful〕〔gently curious〕のように slightly・gently を付ける。〔excited〕〔surprised〕のような強い感情は使わない。
  - 吐息・笑い・ため息（[sighs] など）は使わない。
  - 例：`返ってきたのは、ひとつだけです。〔間〕〔slightly thoughtful〕でも、それは彼のせいでしょうか？`
- **文の頭に「では、」を置かない**（2026-10-06 1本目 v3）：eleven-yui（ElevenLabs v4）は、文頭の「では、」を「では、では」と2回読むことがある（「では、一年後。」のような短い文で起きやすい）。「一年後、〜でしょうか。」のように前置きなしで始めるか、「それなら、」などにする。

## 8. 心の動き（2026-10-04 オーナー指示）

見ている人の気持ちを設計する。確かめるのは `.claude/agents/review-flow.md`。

- **いつも問いを1つ抱えさせる**。前の問いに答えたら、すぐ次の問いを開く。問いのない説明だけの区間を30秒以上続けない。
- **驚きの山は章に1回、後ろほど大きく**。章や動画を、山が下がったまま終えない（「まだ分かりません」で終えるなら、その次に分かっていることで持ち上げる）。
- 予想タイムの答えは最後まで引っぱる。章の中の小さな答えは、引っぱりすぎない（10〜20秒）。
- 締めの気持ちは「なるほど」。判定が△のときは、どっちつかずに聞こえないよう、何の条件で変わるかを一言で言う。

## 9. 深さ（2026-10-04 オーナー指示）

誰でも想像できることの先に、データに裏付けられた気づきを置く。確かめるのは `.claude/agents/review-depth.md`。

- 書く前に、見る人が最初から予想していること（通説・ニュースで聞く話）を構成案に書き出す。
- 章ごとに、その予想の先にある発見を1つ以上置く。予想どおりの確認だけの章にしない。
- 教訓は、このテーマ以外にも使える「ものの見方」にする（例：割合と数を分けて見る、仕組みが結果を決める）。第2章の言い直しで終えない。
- **よくある説明を先に退ける**（毎回。2026-10-06 オーナー指示）：予想タイムの選択肢に、通説やよく言われる説明を入れる。章の中でそれを1つずつデータで退けてから、本当の答えを出す。社会部部長は「勉強不足」を国際学力調査で、「英語教育が悪い」を過去の検証で退けてから、3つ目の答え（米と小麦）を出していた（`research/benchmark/channels-2026-10-05.md`）。
- **条件で答えがひっくり返るときは、その条件を具体的に見せる**（その内容になる回だけ。毎回の型にしない）：判定が△になる回などで、「どの条件で答えが変わるか」を組み合わせ（例：地位が低い×権力が高い）で言い、100人を2×2に分けるなどして見せる。れもんのパワハラの回の型。
- **その回でしか言えない見方が言えるときは、それを教訓にする**（その内容になる回だけ。毎回むりに作らない）：「大事なことは見落とされがち」のような、どの回にも当てはまる一般論で済ませない。社会部部長の締めはこの一般論で、広告へのつなぎに使われていた。
- 深める材料が足りないときは、推測で埋めずに、調べ先を探してから書く。
- **発見には「なぜ」を置く**（2026-10-06 オーナー「データからへーって思うだけで納得感がない」）。「いつ・何と一緒に動くか」で止めず、裏付け（別のデータ・研究）か、数字から立てた仮説を1段置く。仮説は「仮説です」と言い、片側の数字だけで組まない（004 では夫の育児の減りだけを見て、妻の育児がもっと大きく減っていたのを落とした）。

## 10. レビューで繰り返し出た指摘（1本目で学んだこと。2026-10-04）

1本目（`episodes/001-where-couples-meet/review/`）の3回のレビューで出た指摘のうち、ほかの回でも起きやすいもの。書く段階で避ける。

- **研究の時期を越えて、今の話にしない**。古いデータの研究で「いまの若い人は〜ではない」と言わない。「少なくとも〇〇年代までは」と範囲を言い、いまの逆向きの数字があれば一緒に出す。
- **割合の増減を、数の増減のように言わない**。「ほぼ倍に増えた」は「割合がほぼ倍になった」と言う。全体の数が減っているときは特に。
- **調べ方が変わった年を起点にしない**。選択肢がなかった年を0として比べると、増え方が大きく出る。選択肢がそろっている年どうしで比べる。
- **推計の幅を越えて言い切らない**。標本が小さい推計は「推計で〇割ほど」「少なくとも〜とは言えない」まで。山を作りたくても、誤差の上限で崩れる言い方はしない。
- **調査の対象を取り違えない**。夫婦か個人か、未婚者全体か交際相手のいない人か、調査年か結婚した年か。
- **答えを先にもらさない**。予想タイムの答えにつながる順位や並びを、判定より前に言わない（当てはめの場面や章の終わりで、うっかり言いやすい）。
- **同じ数字を何度も読み上げない**。2回目からは「同じ4年で」のように受ける。


## 11. 面白さの仕掛け（2026-10-05 オーナー指示）

考えすぎる葦の最上位の1本（50万回）とデータで語る棒人間の同じ話題の1本（57万回）の分解から（`research/benchmark/teardown/`。1本ずつの分析なので仮説）。相手が強い語りと構成は仕掛けとして取り入れ、相手にないもの（自分で数えた日本の数字・絵で分かる瞬間・見る人の参加・個人の戦い方）で上回る。確かめるのは `.claude/agents/review-rival.md` と `scripts/lint_script.py`。

### 企画カード（構成の前）

`outline.md` の一番上の表（痛み・逆説の一文・この動画だけの数字・日本の数字・絵で分かる瞬間・ミクロ）を埋めてから構成を書く。1つでも空なら、テーマか切り口を変える。

### 台本に置く仕掛け

|---|---|---|---|

| 先回り | `<!-- 仕掛け: 先回り -->` | ○ | 「ここまで聞くと〇〇だと思うでしょう。でも…」。見る人が先を読んで離れそうな所（たいてい第1章の終わり）で、予想を言葉にしてから裏切る |

### ミクロ（個人の戦い方）の見せ方

オーナーの考え：仕組み（マクロ）だけでなく、個人に当てはめるとどう動くのがよいか（ミクロ）が見る人にとって大事。

- **データかシミュレーションで比べた結果として見せる**。「〇〇すべき」「おすすめ」とは言わない。言い方は「100人の町で、〇〇した人は△人、しなかった人は□人が結ばれました」「条件をこう変えると、結果はこう動きます」。決めるのは見る人。
- 比べる戦い方は2〜3個。どれも仮定の世界の結果だと画面の隅に出す（「シミュレーション（条件は概要欄）」）。
- 健康・お金の回は、ミクロの代わりに**示唆**を置く（2026-10-05 オーナー：助言はしないが示唆は明確に）。示唆とは、データから言えること・言えないことと、読み方や前提ごとに過去のデータでどんなリスクとリターンがあったかを、はっきり言い切ること。決めるのは見る人。「〜すべき」「〜を買え」「おすすめ」は言わない。過去の数字は将来を約束しない、と画面の隅に出す。印は `<!-- 仕掛け: 示唆 -->`（ミクロの印の代わりになる）。
- 特定の性別だけに向けた戦い方にしない。男女の回は両方の側の戦い方を出す。
- 置き場所は第3章の後半か答え合わせのあと、教訓の前。教訓（ものの見方）とは別にする。
- シミュレーションの回は、はしごの最後の段として作る：原因が出そろった世界で、1人の戦い方だけを変えて回す（例：いいねを送る数、狙う相手の幅）。

### 書かないこと

- 研究の強さを言い過ぎる、相関を因果のように言う、確かめられない引用を使う（相手の弱いところ。うちは真似しない）。
- 仕掛けのために数字を盛らない（10章）。

## 12. 納得の作り方と、耳だけで伝わる原稿（2026-10-05 オーナー指示。3本目の第2稿「全然おもしろくない」から）

- **冒頭の物語は小説の水準で書く**。「飲み会の帰り道に友人が話す」のような、どこかで見た場面を使わない。その人だけの具体（時刻・手の動き・画面の数字・言いよどみ）を置き、主題の仕組みそのものが物語の中で起きるようにする（例：検索画面で条件を足すたびに数字が動き、足しても減らない条件がある）。書いたら「この場面は、ほかのチャンネルの冒頭と入れ替えても通じるか」を自問し、通じるなら書き直す。
- **学術的な学びを1つ以上入れる**。公的統計だけで終えると「ふわっと」する。論文・研究の結果を1つは主役級に置き、何を調べて何が分かったか（誰を・何人・どの国・何年）を声で短く言う。研究が言っていないことは言わない。
- **耳だけで伝わるように書く**。YouTube Premium などで画面を見ずに聞く人がいる。「左を見てください」「この線が」だけに頼らず、何と何を比べ、どちらが多いかを言葉で言う。数字の比較は「AはB人、CはD人」のように声で完結させる。画面は理解を速める補助にする。
- **シミュレーションより、納得できる学び**。シミュレーションは仮説として「ふーん」で終わりやすい。見る人が納得するのは、①意外なデータ、②感覚的に分かっていたことが、データや論理で裏付けられて見えるようになったとき。シミュレーションは、その裏付けを見せる道具として使う。

## 13. くどさを消す・小説家の水準の日本語・一貫性（2026-10-07 オーナー。007 の読み上げで）

オーナー：「クイズ的なのは最初の答え合わせでよい。それ以降はくどい」「内容は小説家が見るレベルで見てほしい。日本語の使い方が違和感がある所が多く、最大限仕組みとして省いてほしい。一貫性としておかしくないか、も含めて」「そこがなければ台本の構成自体を変えてもよい」。

### クイズは冒頭の予想タイムだけ

- 答えを当てさせる問い（「〜だと思いますか」「考えてみてください」「何でしょうか。〔間〕答えは〜」、選択肢を読み上げる形）は、冒頭の予想タイムの1回だけ。答えは答え合わせで出す。
- 章の中では、**答えを先に言い、そのあとに意外さを語る**（「報告の8割は、人の手のミスでした。外からの不正アクセスは、1割に届きません」）。「答えは、」で明かさない。
- 章の中の問いは、見る人に抱えさせる問い（「なぜ、それほど安いのでしょうか」）と、章の終わりの次への問いだけにする。問いかけて〔間〕で答えを待たない。1章に3つまで。
- 見返される場面（自分に当てはめる・日ごとの再現・実験）は残す。問いの形にせず、「ログインするサービスが二十を超えるなら、あなたは、たくさん使う層にいます」のように言い切る。
- チェッカーは、章の中の「だと思いますか」「考えてみてください」と、文頭の「答えは」をエラーにする。

### 小説家の水準の日本語

書き終えたら、1文ずつ次を確かめる。確かめる役は `review-novelist`（小説家）。

- **語の結びつき**：主語と述語がかみ合っているか（「窓口は2倍あまりです」✕：窓口は量ではない。「景色が逆になります」✕）。
- **副詞と述語の呼応**：「少なくとも〜ほど」のような食い違い。
- **抽象名詞で逃げない**：「〜の形です」「〜という構造」「〜の側」より、何が起きたかを動詞で言う。
- **翻訳調にしない**：「〜することができます」「〜において」「〜を持っています」「〜となります」。
- **言葉の温度をそろえる**：物語は小説の文、解説は落ち着いた話し言葉。物語の中に解説の言葉を入れない。
- **同じ語を近くで繰り返さない**（わざとの対句は残す）。

### 一貫性

- **呼び名を固定する**：同じものは最後まで同じ名前で呼ぶ。別のものに同じ名前を使わない。比喩の言葉（「質屋の窓口」の「窓口」）は、ほかの所で字義どおりに使わない。
- 呼び名は回ごとに `episodes/<回>/wording.tsv`（`scripts/wording.tsv` と同じ形：表記・言い換え・理由）に書く。チェッカーは、その回の表にある「使わない言い方」をエラーにする。小説家役が表の案を出す。
- **比喩の対応**：置いた所と回収する所で、たとえの中の物が指す現実を同じにする。
- **主張の強さ**：本文で「言えません」としたことを、判定・教訓・締めで言い切らない。逆に弱めない。
- **数字の受け方**：同じ数字は同じ丸め方で受ける（「約」「ほど」「あまり」「以上」をぶらさない）。
- **人物**：主人公が現実にそうする行動か。作り手しか知らないことを主人公に考えさせない。冒頭と教訓で状況を食い違わせない。
- **開いた問いは閉じる**：冒頭と章の終わりで開いた問いに、どこで答えたかを確かめる。

### 構成を変えてよい

クイズや言い直しを消すと流れが変わるときは、章の中の順番を組み直してよい（オーナー）。数字・事実は足さない。
