# 台本の推敲

台本（`episodes/<回>/script.md`）を、`docs/script-style.md` の決まりに合わせて直す。
AIっぽい言い回しの直し方は yomiyasu（https://github.com/nanaism/yomiyasu 、MIT License）の考え方を参考にした。

## 最優先

1. **意味を変えない**：主張、比重（何をいちばん大事にしているか）、言い切りの強さ、文の働き（説明・評価・問い）を保つ。推量を勝手に断定にしない。断定を勝手に弱めない。
2. **足さない**：元にない数字・原因・例・人物・出典を足さない。足りないときは本文で補わず、最後の「オーナーに確かめたい点」に書く。
3. **数字を変えない**：丸めるとき（28.25% → 約3割）は、丸めた言い方が元の値と食い違わないか確かめる。丸めで意味が変わるなら、丸め方をオーナーに確かめる。細かい値は台本のメモ（`>` の行）に残し、画面に出す。

## 手順

0. **構成の段階（台本を書く前）**：`outline.md` の一番上の企画カード（痛み・逆説の一文・この動画だけの数字・日本の数字・絵で分かる瞬間・ミクロ）が埋まっているか確かめる。空があれば台本に進まない。埋まったら、書いた会話とは別のサブエージェント `review-rival` に構成案を見せ（`review/rival-outline.md`）、負けている項目を構成で直してから台本を書く。
1. `docs/script-style.md`、`docs/owner-feedback.md`（オーナーの指摘集。過去と同じ型の指摘を先回りで直す）と、その回の `outline.md`・`sources.csv` を読む。
2. `python scripts/lint_script.py episodes/<回>/script.md` を実行する。
3. エラーをすべて直す。注意は1つずつ読み、直すか残すかを決める（物語の中の数字、調査の正式名など、残してよいものもある）。
4. チェッカーでは分からない所を、通して読んで直す。
   - 冒頭が物語（1人の人物・情景）から入っているか。最初の1割に、物語の中で数字が1つ出るか。
   - 章ごとに、視聴者が自分で答えを考えられる場面があるか。
   - 第2章で、もう一方の側のデータが出ているか（男女の回は両方）。
   - 締めが、答えのあとの教訓（一般化）になっているか。教訓が助言になっていないか。
   - 文と文のつながり：つなぎ言葉（しかし・つまり・そのため）と指示語（これ・それ）が、何と何をつないでいるか。耳では前に戻れないので、指す先が直前の1文にないなら名詞に戻す。
   - 予告だけの文（「ここで注目したいのは、次の点です」）は、中身の文と1つにする。
   - AIっぽい言い回し（`docs/script-style.md` 5章）。言い回しの含み（「ようやく」「〜てしまった」など）は、別のふだんの言葉で残す。定着した慣用句と、冒頭の物語の情景の比喩は残す。
   - 煽り・見下し・性別全体の決めつけがないか。
   - 面白さの仕掛け（`docs/script-style.md` の11章）：先回り・比喩と回収・ミクロ・締めの一文の印が置いてあり、印の所に本当にその仕掛けがあるか（印だけ置いて中身がない、を見逃さない）。章の最後の文が次の章への問いか。
5. もう一度チェッカーを通し、エラーが0になったことを確かめる。
6. **別の目でのレビュー**（2026-10-04 追加、2026-10-05 ライバル役を追加）：書いた会話とは別のサブエージェントに、5つの役を並行で頼む。書いた本人のレビューだけで済ませない。
   - `review-facts`（事実確認）、`review-policy`（収益化ポリシー）、`review-flow`（心の動き）、`review-depth`（深さ）、`review-rival`（考えすぎる葦と比べて勝っているか）。定義は `.claude/agents/`。
   - 5役の指摘を直したら、直した稿を事実・ポリシー・心の動きにもう一度見せる（直しで新しい誤りが入りやすい。004 では救いを足した直しで切り取りが2回入った）。
   - 最後に `review-japanese`（日本語役：耳だけで一度聞いて分かるか）に見せ、〔重〕を0にする（2026-10-06 オーナー「日本語レビュワーもいれたいね。仕組みとして」）。
   - 先に `python scripts/check_sources.py episodes/<回>` を通しておく（出典の印・丸め・照合の残り）。
   - 結果は `episodes/<回>/review/` に役ごとに出る。読んで直すものを決め、`episodes/<回>/review/README.md` に「直した／直さなかった（理由）」を1行ずつ書く。
   - オーナーに指摘された点は、同じ間違いを繰り返さないよう、チェッカーかレビュー役の観点に1行足す。
7. 読み上げ用のテキストが要るときは `--tts-out` で書き出す。

## 報告の形

推敲のあと、次の3つを短く書く（オーナーは差分を読まなくてよいように）。

- **直したところ**：種類ごとに1行（例：「小数の読み上げを丸めた（3か所）」「AIっぽい前置きを消した（2か所）」）。
- **残したところ**：チェッカーの注意のうち、直さなかったものと理由。
- **オーナーに確かめたい点**：最大3つ。数字の丸め方、足りない情報、言い切ってよいかの判断など。

★ 一次資料との照合と、読み上げての確認はオーナーが行う（省略しない）。
